## 맥락

- kevin 이 느낀 문제: "깔끔해 보이면서도 정리가 안 된 느낌", 상세가 "확대하기" 같음, 경쟁사보다 뒤처져 보임. 코드로 보면 — 제목 규칙이 사례마다 달랐고(상판 컬러·가구 색·기법이 섞임), 분류는 영어·제목은 한글·소재는 영어였고, 상세에 들어가도 한 줄 설명뿐이었다.
- 결정(시안 이미지로 고름): 표기 "두 줄 + 컬러 칩"(제목 = 컬러 + 용도, 아랫줄 = 지역 | 소재) · 상세는 독립 페이지 **갤러리형**(큰 사진은 한 장만, 나머지는 작은 사진) · 사진은 지금 있는 것만 · 컬러는 사진 보고 가장 비슷한 LX 제품으로 일단 연결 · 지역은 임의(나중에 kevin 이 수정).
- 탈락한 안: 팝업 창(목록 위에 뜨는 창) — "싫다". 사진 두 장을 같은 크기로 위아래 배치 — "각도가 달라서 부산스럽다". 모자이크(대표 + 사이드를 한 틀에) — 갤러리형이 "훨씬 낫다".
- 구조: `data/cases.json` → `scripts/build-portfolio.js` → 생성물. x-dc(React) 를 쓰지 않는다 — 검색·공유 미리보기 때문.
- 사진 폴더가 지역과 어긋나는 3건: 판교 = `yeouido` 와 같은 주방(정리된 버전), 동탄 = `seolleung` 과 같은 회의실, 운정 2번째 사진 = `misa`. 실제 지역은 kevin 확인 필요.
- 새 현장 사진은 kevin 의 구글 드라이브 `직접 수정한거` 폴더에 현장별 폴더로 들어온다. 폴더 이름 = `날짜 [거래처] 지역 소재 컬러`. 거래처 이름(주방 가구 업체)은 사이트에 적지 않는다. 2026-11-26 에는 폴더 7개 중 `11월 11일 … 전시장 인천` 과 `… 인천 서구` 가 같은 사진이라 한 건(`incheon-seogu`)으로 합쳤고, 용산 2.jpg·3.jpg 도 같은 파일이었다.
- 실제 컬러를 아는 사례의 제목은 `컬러 이름 + 주방 형태`(예: 베이지 바살트 아일랜드 주방, 트라몬토 일자 주방).
